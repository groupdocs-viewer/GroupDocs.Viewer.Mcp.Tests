# Target GroupDocs.Viewer.Mcp 26.7.0 + add Cursor how-to

## What changed
- `Directory.Build.props` `<McpPackageVersion>` default → `26.7.0`.
- `.github/workflows/integration.yml` `workflow_dispatch` default and the
  `MCP_PACKAGE_VERSION` fallback → `26.7.0`.
- Bumped every usage `@`-pin (dnx args, Docker tags, `--version` examples) across
  `how-to/*`, `examples/*`, `docker-scripts/*`, `README.md`, and `AGENTS.md` to
  `26.7.0`.
- Added `how-to/07-use-with-cursor.md` + `examples/cursor-mcp.json` — Cursor uses

  SSL/timeout workaround (full `dotnet.exe` path + cached DLL).
- Corrected a Metadata-era inaccuracy in `how-to/README.md`: `render_page`
  renders in evaluation mode (watermarked PNG), it does not refuse to `Save()`.

The main server published `26.7.0` (descriptive error handling via shared
`ToolError`, Dockerfile MS core fonts). The integration suite must target the
same version. Tool surface is unchanged (2 tools: `render_page`, `get_view_info`);
`ToolDiscoveryTests` still asserts a count of 2.

## Migration / impact
Test-only change. No new tests; existing tests run against `26.7.0` once it is
indexed on nuget.org. Override with `-p:McpPackageVersion=<x.y.z>` or the
`MCP_PACKAGE_VERSION` env var as before.
